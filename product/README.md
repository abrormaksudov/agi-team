# Product

What we pitch.

- `openmetadata/` — catalog deployment and ingestion configs
- `agent/` — AI agent backend (Python, Compose service `agent` in `openmetadata/compose.yaml`; design in [docs/agent.md](../docs/agent.md))

## Demo server

- Cloud server `agi-demo`, Tashkent; Ubuntu 24.04 LTS, x86_64, 4 vCPU / 16 GB / 100 GB SSD.
- Public catalog: <https://157-22-137-126.sslip.io> (Caddy, HTTPS; [docs/catalog.md](../docs/catalog.md), Public entry).
- **What runs there** (from `/opt/agi`, a git checkout of the deployed commit): the lab stack (`cd /opt/agi/lab && docker compose …`, project `agi-lab`) and the catalog stack (`/opt/agi/product/openmetadata`, project `agi-catalog`, incl. the Caddy proxy: Compose profile `public`, so a manual `docker compose` there needs `--profile public`). Lab data at 10k persons, played 2026-07-31 … 09-30.
- **Deploy on demand, never on push:** `gh workflow run deploy.yml` (head of `main`; `--ref <tag>` for a tagged commit), then `gh run watch`; or Run workflow in the Actions tab. GitHub Actions (`.github/workflows/deploy.yml`; history under Deployments → `agi-demo`) logs in with its own key, checks the commit out in `/opt/agi` and runs `tools/deploy/deploy.sh`: both stacks `up` (images rebuilt only when their inputs changed; Liquibase DDL, dbt parse + Airflow DAGs and OM migrations rerun every time; the source DDL comments are replayed and the proxy reloads its config), then `catalog/apply.py`, then a smoke test of the public URL. About 75 s without image builds, ~4 min with them. New descriptions or row counts reach the server catalog only when its pipelines run: `ssh agi-demo 'cd /opt/agi && python3 product/openmetadata/catalog/apply.py --trigger <pipeline>…'`. Running version: `git -C /opt/agi log -1`; one line per deploy in `/opt/agi-logs/deploys.log`. Never edit files on the server: the next deploy overwrites them. A new stack or service ships by adding it to `tools/deploy/deploy.sh`, with its image inputs in the rebuild check there (the `agent` image is rebuilt when `product/agent/` changed).
- **Data operations stay manual** (they change data, not code), over SSH after the deploy: a model on the last day `labdbt 2026-09-30 build --select <model>`; trigger every catalog pipeline `python3 /opt/agi/product/openmetadata/catalog/apply.py --run` (~10 min, log to `/opt/agi-logs/`), or some of them `… apply.py --trigger greenplum_dbt lab_airflow_metadata`. Each `dbt__cod` run ends by compiling the project for the catalog (column lineage, the dbt tab's SQL) and running all tests (test results); after a deploy that changed dbt models or YAML, refresh both without replaying a day: `DBT_WRITE_JSON=True labdbt 2026-09-30 compile --target-path /opt/airflow/dbt-state/catalog`, `DBT_WRITE_JSON=True labdbt 2026-09-30 test`, then `--trigger greenplum_dbt` (otherwise the next day's run does it).
- **Helpers on the server PATH** (symlinks to `/opt/agi/lab/ops/`): `gpsql`, `labdbt`, `labbackfill`, `labday` ([docs/lab.md](../docs/lab.md), Ops scripts). Logs of long runs: `/opt/agi-logs/`.
- Load: lab + catalog use ~6 GB RAM; 4 vCPU are the limit when Airflow and catalog ingestion run together (load ~12, everything slower, nothing fails).
- Access: SSH keys only (password login off). GitHub Actions uses its own key, prefixed `restrict` (commands only, no forwarding or terminal); its private half lives only in the repo secret `DEPLOY_SSH_KEY`.
- Private UIs bind to 127.0.0.1 on the server; an SSH tunnel (`ssh -N -L 8585:127.0.0.1:8585 -L 8080:127.0.0.1:8080 -L 8081:127.0.0.1:8081 agi-demo`) forwards them to <http://localhost:8585> (catalog), <http://localhost:8080> (OM ingestion Airflow) and <http://localhost:8081> (lab Airflow) while it runs.
- Server setup: unattended security upgrades, timezone Asia/Tashkent, 8 GB swap (`vm.swappiness=10`), `vm.max_map_count=262144` for Elasticsearch, Docker 29.9 + Compose v5.6 (log rotation 3×20 MB), git, `ufw` allowing only 22/80/443.
